## Method: Three-Component Metric

**MACE = f(S_audio-text, S_text-text, Fluency_penalty)**

### Component 1: Audio-Text Score
```
S_audio-text = cos(E_a(A), E_t(C))
```
- E_a(A) = CLAP audio embedding of source audio
- E_t(C) = CLAP text embedding of candidate caption
- Measures: does the caption match the actual audio?

### Component 2: Text-Text Score
```
S_text-text = (1/n) Σ cos(E_t(C), E_t(R_i))
```
- Cosine similarity between candidate and reference captions in CLAP text space
- Measures: does the caption match what humans wrote?

### Component 3: Fluency Error Penalty
- BERT-based fluency detector (from FENSE)
- Penalises incomplete sentences, repetitions, grammar errors

### Key Innovation
- **First metric to use the audio signal itself** during evaluation
- All existing metrics (BLEU, ROUGE, CIDEr, SPICE, SPIDEr, FENSE) compare text-to-text only
- MACE can evaluate **without reference captions** by using only Component 1 + 3

## Metric Taxonomy (from Related Work)

The paper provides a useful taxonomy of AAC evaluation:

1. **Linguistic metrics:** BLEU, ROUGE, METEOR — n-gram overlap
2. **Graph-based:** SPICE — object-graph comparison
3. **Combined:** CIDEr (TF-IDF n-gram), SPIDEr (SPICE + CIDEr)
4. **Embedding-based:** FENSE, BERT-Score, BLUERT — sentence embeddings
5. **LLM-based:** CLAIRA — LLM-as-judge, numeric score 0–100
6. **Multimodal:** **MACE** — audio + text + fluency (this paper)

## Relevance to RQs

- **RQ1 (Baseline Parity):** ★★★ MACE should be included alongside SPIDEr-FL and CLAPScore in evaluation battery.
- **RQ2 (Polyphony):** Audio-grounded evaluation may detect when models miss concurrent events that text-only metrics wouldn't catch.
- **RQ3 (Hallucination):** If a model hallucates "dog barking" but no dog exists in audio, S_audio-text should be low even if reference text also mentions dogs.

## Critical Insight for This Project

MACE solves a fundamental problem: existing metrics can give high scores to captions that match *references* but not *reality*. If reference captions themselves are biased (e.g., always mention salient events, ignore background), text-only metrics reinforce that bias. MACE breaks this cycle by anchoring evaluation in the audio signal.

## Limitations / Gotchas

- Depends on CLAP quality — if CLAP has poor representations for certain sounds, MACE inherits those blind spots.
- CLAP was trained on specific audio types — unknown coverage for soundscape-specific sounds.
- Newer metric — less community adoption, no DCASE leaderboard integration yet.
